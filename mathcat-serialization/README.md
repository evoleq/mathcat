# MathCat serializable type registration — runtime + optional KSP

The serialization *runtime* lives in `mathcat-serialization`, with a single portable `Serializers` registry type. Every Gradle module chooses how to produce its registry. Both choices can be combined without a global mutable map.

## Manual (no code generation)

```kotlin
val userSerializers = Serializers {
    add<Login>(Login.serializer())
    add<LoggedIn>(LoggedIn.serializer())
}
```

Only depend on `mathcat-serialization` and use the usual Kotlin serialization compiler plugin for `@Serializable` classes.

## Generated (opt-in KSP)

Apply `com.google.devtools.ksp` **in the consumer module**, and add `ksp(project(":mathcat-serialization-ksp"))` (or the published processor dependency). The processor registers **all eligible `@Serializable` classes in the compilation's source files**, unless excluded using `@SkipAutoSerializer`. This is a build-time tool: it is not added to the application's runtime classpath.

```kotlin
@Serializable data class Login(val user: String)
@SkipAutoSerializer @Serializable data class InternalOnly(val id: String)

// Generated by KSP in the selected output package:
val GeneratedSerializers: Serializers = Serializers {
    add(Login::class, Login.serializer())
}
```

The real generated output defaults to package `org.evoleq.mathcat.serialization.generated`, symbol `GeneratedSerializers`. Optional KSP args `mathcat.serializers.package` and `mathcat.serializers.name` customize them. **Do not declare the generated property manually.** See the compile-tested consumer `mathcat-serialization-ksp-fixture` for Gradle setup.

## Mixing, duplicates and explicit replacement

```kotlin
val appSerializers = Serializers {
    include(GeneratedAuthenticationSerializers)
    include(ManualBankingSerializers)
    add<SpecialType>(SpecialTypeSerializer)
    replace<Login>(CustomLoginSerializer) // only if already registered
}
```

`add` and `include` reject duplicate KClass registrations. `replace` is the only intentional override, and rejects missing entries. The finished `Serializers` value is an immutable snapshot. Runtime has **no KSP or Ktor dependency**; `mathcat-api` is not modified.

## Explicit limitations

- KSP registers *source-declared* non-generic, visible serializable classes, objects, enums and sealed interfaces. It skips generic declarations (logged with a warning), annotated `@SkipAutoSerializer` classes, nonpublic classes and imported dependency classes. Register generic instantiations and custom serializers manually. Sealed class semantics remain Kotlinx Serialization's responsibility.
- The registry uses `KClass` keys and therefore **does not distinguish** `List<User>` from `List<Order>`. Compose parametrized serializers explicitly using `ListSerializer` or `MapSerializer`.
- Each independent Gradle module can generate its own registry and contribute it to a composition root; no automatic whole-application scan.
- The KSP processor uses KSP2 `2.3.12`, whose current compatibility range covers Kotlin `2.3.20`. It is in a separate JVM build module in the **MathCat repository**; this does not reuse `fp-axioms` runtime or force an extra Gradle convenience plugin.
- Result wire compatibility, `ResultSerializer`, Ktor Client/Server and multi-target KSP consumer integration are **separate follow-up slices**. No Solyton migration is implied. Publication via JitPack requires separate consumer/CI verification before a tag/release.

## Typed Result wire format

ResultSerializer(payloadSerializer) serializes and deserializes the existing Solyton JSON fields type/classType/data/message. A compile-time typed payload serializer replaces the unsafe global lookup by class simpleName. JSON golden tests preserve the old Success and Failure format; ListSerializer supports generic payloads. The numeric HTTP status remains separate transport metadata handled by Ktor. The Ktor-free mathcat-result module provides the familiar Result algebra and independently composed ExceptionTransforms for domain-specific status and error messages. No Ktor or app changes are made here.
